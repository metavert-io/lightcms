# Security guidance: metavert-io/lightcms

Generated by the Security Steward from `security/threat-model.yaml` (model v1, reviewed at 81707877bb8d). Edit the model, not this file.

A multi-user Go and MongoDB CMS (metavert.io): an admin UI, a REST API, an authenticated MCP server with OAuth 2.1 for connectors, a public read-only MCP endpoint, a public chat widget and search. It also publishes an MCP container image.

## What this system protects

- C1 Admin UI (/cm) (internet)
- C2 REST API (/api/v1) (internet)
- C3 Authenticated MCP server (/mcp) (internet)
- C4 Public MCP endpoint (/mcp-public, read tools) (internet)
- C5 OAuth 2.1 server for MCP connectors (internet)
- C6 Public chat widget (internet)
- C7 Uploads and assets (internet)
- C8 System API key
- C9 MongoDB (internal)
- C10 Published MCP container image (internet)
- C11 Outbound fetches (webhooks, RSS, asset-from-URL, link checker)

## Assumptions

- A1: The app runs on Fly behind its proxy, which sets Fly-Client-IP.

## Keep in mind when changing code

- T-LC-0001 (mitigated, STRIDE:I STRIDE:T CWE-918 ASVS:5.0.0:V12): Outbound fetches are pointed at internal or metadata addresses (SSRF). Relies on M-LC-0001
- T-LC-0002 (mitigated, STRIDE:S CWE-348): A client spoofs its address to dodge per-client limits. Relies on M-LC-0002

## Controls that must stay in place

- M-LC-0001: netguard SSRF guard on every outbound fetch (`internal/netguard/netguard.go`)
- M-LC-0002: Client address taken from Fly-Client-IP (`internal/middleware/apiauth.go`)
